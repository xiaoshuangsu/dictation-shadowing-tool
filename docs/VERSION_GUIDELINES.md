## 📋 版本号体系说明

本项目采用**统一的语义化版本号体系**（Semantic Versioning），避免多版本号并存的混乱。

## 🎯 统一版本号

### 主项目版本号

**位置**: `package.json` 中的 `version` 字段

**格式**: `v主版本号.次版本号.修订号` (如 `v22.0.0`)

**规则**:
- **主版本号**（Major）：重大功能变更、不兼容的 API 修改
- **次版本号**（Minor）：新功能、向后兼容的功能增强
- **修订号**（Patch）：Bug 修复、小的改进

**示例**:
- `v20.0.0` → `v21.0.0`：新增越南语翻译功能
- `v22.0.0` → `v22.1.0`：新增某个小功能
- `v22.1.0` → `v22.1.1`：修复 Bug

## ❌ 已弃用的版本号标记

### 历史遗留问题（3月18-20日）

在此期间，部分 commits 使用了功能模块版本号标记，这不再推荐：

| 标记类型 | 示例 | 说明 |
|---------|------|------|
| 翻译脚本版本 | `V21`, `V20.1` | ❌ 已弃用，使用主版本号 |
| 功能模块版本 | `v1.2.0`, `v1.2.7` | ❌ 已弃用，使用主版本号 |

**原因**：
- 导致版本号混乱
- 难以追踪项目整体状态
- 与语义化版本号冲突

## 📝 Commit Message 规范

### ✅ 推荐的 Commit Message 格式

```
<type>: <简短描述>

<详细说明（可选）>

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>
```

**Type 类型**:
- `feat`: 新功能
- `fix`: Bug 修复
- `docs`: 文档更新
- `chore`: 构建/工具链更新
- `refactor`: 代码重构
- `perf`: 性能优化
- `style`: 样式调整

**示例**:
```
feat: 新增越南语翻译支持

完成201个素材的越南语翻译，覆盖6种翻译风格

Co-Authored-By: Claude Sonnet 4.5 <noreply@anthropic.com>
```

### ❌ 不推荐的 Commit Message 格式

```
feat: 优化单词挖空逻辑 v1.2.0  ❌ 不要加功能版本号
feat: 添加 V21 翻译脚本         ❌ 不要加脚本版本号
```

## 🔄 版本号更新流程

### 更新版本号的步骤

1. 修改 `package.json` 中的 `version` 字段
2. 提交 commit：`chore: bump version to x.y.z`
3. 更新 `CHANGELOG.md`，添加版本更新说明
4. 推送到 GitHub

### 示例

```bash
# 1. 修改版本号
vim package.json  # 改为 "version": "22.1.0"

# 2. 提交
git add package.json
git commit -m "chore: bump version to 22.1.0"

# 3. 推送
git push origin main
```
